# 1. MATRICE D'ÉTATS

Machines d'état pivots : `screen` (splash→login→register→onboarding→setup→main) · `flow` (`carte`→`app`) ·
`tab` · **le GATE** `availableRef = is_available && available_until > now`.

## 1.1 AUTH & GATE

| État | Conditions d'entrée | Actions | Transitions | Invariants |
|---|---|---|---|---|
| `splash` | lancement app | — (auth tourne en //) | → login / main selon session | l'auth ne bloque jamais l'écran > 2,95 s |
| `login` | pas de session / profil absent | email+pw · mot de passe oublié · créer compte | → setup (profil incomplet) · → main (complet) · → register | reset pw = message anti-énumération constant |
| `register` | « créer un compte » | prénom (≤8) · genre · date · email · pw | → onboarding / setup ; garde < 18 ans | genre verrouillé après création |
| `setup` (5 étapes) | profil incomplet | photo(mod. IA) · nom/âge/genre · looking_for · bio · ville | → main | photo + nom + âge + genre OBLIGATOIRES |
| **GATE ouvert** | `is_available && until>now` | voir/agir dans les onglets | → GATE fermé (expiry) | 2 conditions TOUJOURS ensemble |
| **GATE fermé** | pas de dispo active | bannière « pas visible » / mise en ligne | → `flow:'carte'` | invisible aux autres ; premium = « mode discret » |

**Invariant transverse** : une protection JS seule est contournable → toute règle de sécurité vit AUSSI côté serveur (RLS/RPC). *Pièges connus* : `is_available=true` avec `until` expiré EXISTE (flag périmé) → chaque lecteur re-teste les 2 ; `setTab()` ne re-teste plus le gate (devenu soft — cf §G).

## 1.2 CRÉNEAUX (solo : 0 / 1 / 2 / 3)

| État | Entrée | Actions | Transitions | Invariants |
|---|---|---|---|---|
| **0 créneau** | aucune `availabilities` active | « Ouvre un créneau » → `flow:'carte'` | → 1 créneau | invisible ; pas de présences |
| **1 créneau** | 1 ligne active | modifier · supprimer · +ajouter | → 0 / 2 | résumé `profiles` = [start, end] du créneau |
| **2 créneaux** | 2 lignes | idem + pastilles 1·2 | → 1 / 3 | résumé = [min start, max end] de l'union |
| **3 créneaux** (MAX) | 3 lignes | modifier/supprimer ; +ajouter → **le + ancien s'éteint** | → 2 | 4ᵉ impossible : éviction silencieuse du + vieux ⚠️ |
| **chevauchants (temps+espace)** | ≥2 créneaux qui se recouvrent | légitime | — | toast vert « ouvert·e à plusieurs plans » ; l'UNION est la vérité |
| **édition en cours** | ✏️ sur un créneau | tout pré-rempli ; « Modifier ✓ » / annuler | → sauvé / intact | l'ancien n'est éteint QU'APRÈS l'insert réussi (zéro perte) |

**Fonctions** : `handleOuvrirFenetre()` (le confirm), `reloadAvail`/réconciliation `availabilities→profiles`,
`removeSlot`, `mySlotGeoms`. **Invariant clé** : `availabilities` = LA vérité ; `profiles` (résumé) est
recalé automatiquement (0 fenêtre → éteint · fenêtres → [min,max]).

## 1.3 PRÉSENCES (qui je vois)

| État | Entrée | Actions | Transitions | Invariants |
|---|---|---|---|---|
| liste remplie | gate ouvert + ≥1 profil passe les 14 filtres | tap → fiche · pastilles créneau · filtres | → fiche / envoi | tri = intérêts·proximité·fiabilité ; jamais de km exact |
| vide (créneau ouvert) | `filtered=[]` mais `myAvail>0` | modifier créneaux · réessayer | → remplie | l'état vide DIT pourquoi (3 maladies distinctes) |
| vide (fetch échoué) | `presFetch.err` | Réessayer | → remplie | jamais un « 0 » silencieux |
| boîte pleine | pending reçus ≥ **5** | Répondre | → remplie | SYMÉTRIE : invisible + je ne vois plus les autres |
| masqué par mon filtre genre | `filterGender≠all` cache tout | élargir (1 tap) | → remplie | ⚠️ piège X (non-binaire) — réordonné 15.07 |

**Filtre** : `passesPresenceFilters(p)` — 14 conditions ordonnées (bot · verrou · clutch en cours · lapin 48h · boîte pleine · driver · MON genre · SON genre · modes · MON âge · SON âge · union créneaux temps+espace · RDV bloqué · géo fallback). Miroir diagnostic : `excludeReason(p)`.
**Contexte clarifié « paire à intersection maximale »** : aujourd'hui le code croise MES créneaux (union) contre le résumé de l'autre ; il n'affiche PAS explicitement « le meilleur créneau commun ». 🕳️ à spécifier (cf §2).

## 1.4 CLUTCH (envoyé / accepté / refusé / expiré)

| État | Entrée | Actions | Transitions | Invariants |
|---|---|---|---|---|
| **envoyé** (pending, sender) | `create_clutch` OK | annuler (−2) | → accepté / refusé / **expiré (2h)** / annulé | dans « ⏳ En attente » ; l'autre a 2h |
| **à répondre** (pending, receiver) | reçu | valider · refuser · contre-proposer · voir lieu | → verrou / refusé / contre / **expiré (2h)** | dans « 🔥 À répondre » ; le sens est distinct |
| **accepté / verrou** | valider OK | chat · j'y suis · terminer · annuler | → RDV / annulé | occupation forteresse posée ; masqué des présences −1h/+2h |
| **refusé** | refuser | — | historique | cooldown 48h directionnel côté envoyeur |
| **expiré** | +2h sans réponse | — | historique | cron ; jamais `declined` |
| **en pause** (`isPausedClutch`) | pending chevauchant un RDV | — | revit si le RDV saute | calculé, jamais stocké |

**Gardien** : `create_clutch()` (serveur) → self · block · cooldown · **cône** · sender_busy · target_out_of_zone · pair_busy · inbox_full · gender_mismatch. Anti-sonde : block/cooldown/inbox/gender = MÊME message neutre.

# 2. CHEMINS DE DÉCISION & EDGE CASES

Pour chaque transition clé : **A** happy · **B** limites numériques · **C** GPS · **D** malveillance · **E** accidents · **F** races · **G** non implémenté.

## T1 — Ouvrir un créneau
- **A** : lieu + heures + genre + modes → `handleOuvrirFenetre` → dispo posée, retour présences.
- **B** : heure = maintenant pile → `slotEpoch` arrondi ¼h ; fin < début → passage minuit géré ; durée > 18h → clampée ; < 1h → forcée à 1h ; créneau qui « touche » un autre pile → chevauchement = légitime.
- **C** : GPS absent à l'ouverture → repli sur le centre du profil / Lausanne (fail-open) ; pan carte sans fix → « autour de moi ».
- **D** : créneau « impossible » (rayon 1km + lieu à 40km) → le Cône décale le début OU refuse au confirm (message vert re-tape) ; spam de créneaux → max 3, éviction du + ancien.
- **E** : créer 3 puis en supprimer 1 → résumé recalé sur les 2 restants ; abandonner l'édition → créneau intact (zéro perte) ; ouvrir en étant déjà dispo → toast « l'ancien est remplacé » (⚠️ trompeur : il ACCUMULE jusqu'à 3).
- **F** : deux `handleOuvrir` concurrents → `.select('id')` + upsert de secours ; édition pendant qu'un clutch est en vol → l'ancien créneau survit jusqu'à l'insert.
- **G** : 🕳️ **éviction silencieuse du 4ᵉ créneau** sans toast dédié (viole « jamais de jet silencieux ») ; 🕳️ « paire à intersection maximale » pas affichée.

## T2 — Voir / ne pas voir quelqu'un
- **A** : les 14 filtres passent → visible, trié.
- **B** : distance = somme exacte des rayons → `≤` inclusif (visible au pile) ; âge = borne exacte → inclusif ; fenêtres qui se touchent à la minute → `>=`/`<=` (pas de chevauchement si from==until).
- **C** : GPS du viewer périmé → la géo utilise le CENTRE du créneau (fixe), pas la position live → cohérent même si tu bouges.
- **D** : sonder les filtres par requêtes répétées → `excludeReason` admin-only ; positions floutées ~1km ; jamais de km exact (anti-triangulation).
- **E** : filtre genre resté sur X (non-binaire) → écran vide « 456 cachés » → bouton élargir (réordonné 15.07 pour éviter le piège).
- **F** : les 2 ouvrent un créneau en même temps → chacun recharge (10s) → convergence.
- **G** : 🕳️ le gate `setTab` est devenu soft (navigation libre + liste vide) — dérive à confirmer produit.

## T3 — Envoyer un Clutch
- **A** : heure + lieu (dans la zone rose) → `create_clutch` → « envoyé, 2h ».
- **B** : lieu pile sur le bord du cercle → `inZone` inclusif ; heure = maintenant+trajet pile → le Cône informe sans bloquer.
- **C** : GPS de l'envoyeur absent → le Cône ne calcule pas MES minutes (fail-open, pas de blocage).
- **D** : spam → plafond simultané (femmes 20 · hommes 10) ; clutch hors zone → garde ZONE serveur ; re-clutch après refus → cooldown 48h ; deviner l'agenda de la cible via la molette → volontairement NON (anti-oracle, meurt en `sender_busy` à l'accept).
- **E** : envoyer puis fermer sa fenêtre → re-fetch cible avant l'insert → écran doux « sa fenêtre s'est refermée ».
- **F** : **deux clutchs simultanés sur la MÊME personne** → `pair_busy` (un seul clutch actif par paire) ; **modifier son créneau pendant qu'un clutch est en vol** → le clutch garde son lieu/heure figés, la modif ne le touche pas.
- **G** : ✅ couvert par le gardien unique `create_clutch`.

## T4 — Répondre / Verrou
- **A** : valider → occupation posée → Verrou.
- **B** : accepter à l'heure pile où j'ai déjà un RDV → `occ_no_overlap` (23P01) → « déjà un rendez-vous » ; le trou de 3h calculé au pile (−60/+120).
- **C** : — (le GPS n'intervient qu'au check-in).
- **D** : accepter puis ghoster → coupe tout en silence ; contre-proposer en boucle → `declined` terminal (pas de spam).
- **E** : oublier de répondre → expire (2h) ; contre-proposition qui rate → l'original reste intact (transaction atomique).
- **F** : les deux valident le même créneau croisé simultanément → EXCLUDE gist rejette le 2ᵉ (23P01).
- **G** : 🕳️ le catch de `accept()` dans la boîte n'affiche pas le message dédié « cône » (message brut) — cf arbre §🐞.

## T5 — Le RDV, « j'y suis », géométrie
- **A** : à −10min, GPS ≤ seuil → pointer → arrivé ; les deux → terminer.
- **B** : **GPS exactement à 20 m** (spec) / **25 m** (code) → `≤` inclusif → cliquable ; à 600 m pile → `CHECKIN_MAX_KM=0.6` exclusif → bloqué.
- **C** : **perte de signal** → plan B manuel après 15s ; **GPS lag/saut** → une lecture aberrante pourrait débloquer/bloquer à tort (🕳️ pas de lissage/médiane) ; GPS absent tout le RDV → pointage manuel possible si l'autre est arrivé.
- **D** : mentir « j'y suis » à distance → refusé si GPS > seuil (pas de check-in), MAIS le plan B manuel est déclaratif (🕳️ contournable si GPS « absent »).
- **E** : **oublier de cliquer j'y suis** → à la clôture, question « étais-TU là ? » (réponse honnête = 0 pénalité) ; **arriver avec une position changée depuis le Clutch** → normal, le check-in se fait au LIEU, pas à la position du Clutch.
- **F** : les deux pointent à la même seconde → chaque update indépendant (`sender_arrived`/`receiver_arrived`), pas de conflit.
- **G** : 🕳️ **seuil 20 m unifié** (spec) vs 25/100 m (code) — à trancher ; 🕳️ **anti-saut GPS** (lissage) non implémenté ; 🕳️ « GPS absent → PAS de feedback demandé » (spec) vs feedback demandé quand même (code).

## T6 — Feedback, contradiction GPS/parole, réputation
- **A** : j'ai pointé → « l'autre était là ? » → points à +3h.
- **B** : je pointe à la dernière seconde de la fenêtre → compte comme présent.
- **C** : **contradiction** : j'ai pointé GPS mais je dis « il n'est pas venu » alors que LUI a pointé → **le pointage bat la parole** (serveur : « absent » contre un pointé = 0 pt).
- **D** : mentir sur le feedback → double-aveugle (révélation +3h) empêche la coordination ; noter pour se venger → le rapporteur ne gagne/perd jamais de point pour son propre feedback.
- **E** : ne jamais donner le feedback → gate progressif (1 rappel · 2 orange · 3 blocage).
- **F** : les deux donnent un feedback contradictoire → serveur arbitre par le pointage.
- **G** : 🕳️ « GPS absent pendant le Verrou → notif simple + contestable, PAS de feedback » (spec) partiellement là ; 🕳️ **bucket « pattern suspect » observationnel** (accumuler sans punir) non implémenté — aujourd'hui les pénalités s'appliquent direct.

## T7 — Réputation long terme (règle 6 mois)
- **A** : bon comportement → score stable/haut.
- **B/C** : — .
- **D** : récidiviste no-show → multiplicateur ×1,5/×2.
- **E** : une erreur ponctuelle → ne doit pas bannir (lapin 48h, pas à vie).
- **F** : — .
- **G** : 🕳️ **plafond de reset 6 mois** (David 15.07) NON implémenté : le multiplicateur de récidive (compteur localStorage) ne se remet jamais à zéro ; le score ne remonte pas seul. **Décision** : wipe sec 6 mois vs remontée progressive (cf arbre §🐞8).

## 🗃️ « LE CASIER » — proposition Claude pour le point 4 (remplace le wipe sec à 6 mois)

**Principe : le temps seul n'efface rien — le bon comportement efface. Sauf le blocage, qui est une décision humaine et ne s'efface que par une décision humaine.**

- **Fiabilité** : remonte avec les **RDV honorés** (pas en attendant), plafonnée. → un no-show en série ne se refait pas une virginité en dormant 6 mois.
- **Cooldown lapin (A→B)** : A ne peut plus clutcher B pendant **6 mois** (ton intuition, gardée ici car c'est une relation, pas un score).
- **2e lapin de A envers B** → **blocage permanent automatique**, déblocable **par B seulement** (jamais par A). « plus jamais en cent ans. »
- **Multiplicateur de récidive** (annulations) : décroît d'un palier **par période sans incident ET avec RDV honorés** — jamais par le temps seul.
- **Contradiction sans preuve GPS** (A dit « lapin », B dit « j'y étais », personne n'a pointé) → **personne n'est puni, l'incident part au CASIER** (point 3). C'est le bénéfice du doute du point 2, et le motif parle s'il se répète.
