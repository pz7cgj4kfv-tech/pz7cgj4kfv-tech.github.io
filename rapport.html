3. Bugs & vulnérabilités détectés

Simulation agent 16.06
Détectés par simulation automatique de deux bots (Alice + Bob) testant le flow complet via API Supabase.
CRITIQUE
Limite 3 clutchs simultanés non enforced en DB
La limite est 100% côté client JS. Un utilisateur via curl ou app modifiée peut envoyer des clutchs illimités. Testé : le 4ème INSERT passe sans erreur.
→ Ajouter une Edge Function Supabase ou un trigger PG : BEFORE INSERT ON clutches → COUNT actifs par sender → RAISE si ≥ seuil
CRITIQUE
Contrainte CHECK sur rdv_feedbacks.outcome incohérente
La DB rejette les valeurs 'on_time' et 'showed' (seul 'absent' passe). Le code JS envoie ces 3 valeurs. Quand les vrais users feront leur premier feedback positif, ça échouera silencieusement.
→ ALTER TABLE rdv_feedbacks DROP CONSTRAINT rdv_feedbacks_outcome_check; ALTER TABLE rdv_feedbacks ADD CONSTRAINT rdv_feedbacks_outcome_check CHECK (outcome IN ('on_time','showed','absent'));
RISQUE
reliability_score sans trigger DB — bypass possible
Les pénalités lapin et récompenses sont calculées côté client uniquement. Un utilisateur malveillant peut signaler des lapins sans que son score soit affecté.
→ Edge Function AFTER INSERT ON feedback : calculer le delta et appliquer sur profiles.reliability_score côté serveur
INFO
Profils expirés — filtre correct ✅
Les profils passé leur available_until disparaissent bien du filtre serveur (available_until.gt.NOW()). Le gate fonctionne correctement.
→ RAS — validé

8. Principe de design — Poupées russes

Comment gérer la complexité sans surcharger l'UI
L'app grossit vite. La règle absolue : 1 écran = 1 intention. Tout ce qui déborde va dans un sous-menu.

Exemple réussi : Mode Pro dans Présences → bouton 💼 → liste métiers → profils. 3 niveaux, 3 clics, zéro bruit.

Règle : si une feature nécessite plus d'une ligne dans le header → elle a son propre sous-menu. Jamais d'accordéons, jamais de modales empilées. Des poupées russes : on rentre, on en ressort.

Test de Mel : "Est-ce qu'une femme de 23 ans comprend ce qu'elle doit faire dans les 2 premières secondes ?" Si non → reprendre.
